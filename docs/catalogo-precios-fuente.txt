##################################################
REGLAS DE IMPLEMENTACIÓN PARA CODEX
##################################################

1. Crear una estructura centralizada para todos los precios.

2. No escribir los precios directamente dentro de componentes de UI
si pueden mantenerse en un archivo de datos separado.

Ejemplos posibles:
- precios.ts
- productos.ts
- catalogo.ts
- products.json

3. Cada producto debería poder almacenar como mínimo:
- id
- nombre
- categoría
- descripción
- variantes
- tamaños
- cantidades
- precio
- precioUnitario
- precioPack
- cuotas
- notas
- requiereConsulta

4. Si existe más de una opción:
por ejemplo:
- tamaño
- cantidad
- tipo de impresión
- simple faz / doble faz
- infantil / adulto

el precio debe cambiar según la variante seleccionada.

5. NO calcular automáticamente precios para cantidades que no estén
definidas en esta lista.

Ejemplo:

Si existen:
100 = $18.000
300 = $48.000
500 = $75.000

y el usuario pide 200:

NO calcular $36.000.

Debe mostrarse:
"Consultar precio"

6. Cuando un producto diga:
"Diseño personalizado se cotiza aparte"

mostrar claramente:
"El diseño personalizado se cotiza aparte."

7. Cuando diga:
"Por otras medidas consultar"

mostrar:
"Consultar por otras medidas."

8. En productos vendidos por pack, respetar el precio unitario del pack.

Ejemplo:

Remeras adulto:
Pack x10 = $23.000 c/u

Significa:
- cantidad mínima de esa opción: 10
- precio mostrado por unidad: $23.000 c/u

No reemplazarlo por otro precio.

9. Mantener la información comercial exactamente según este catálogo.

10. Si hay alguna duda, dato faltante o variante no especificada:
NO inventar.
Mostrar "Consultar".
